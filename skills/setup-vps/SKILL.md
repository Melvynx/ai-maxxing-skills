---
name: setup-vps
description: Turn the user's VPS into their 24/7 agent: copy their GitHub and Cloudflare access, install Hermes on Claude Code, chat with it on Telegram or Discord, and put its dashboard on hermes.their-domain behind an IP whitelist and a password. Use after connect-vps, or when Hermes is missing.
argument-hint: "[domain, e.g. example.com] [alias, default hermes]"
user-invocable: true
---

Turn the server the user reached with `ssh hermes` into their own agent that runs 24/7: it gets their GitHub and Cloudflare access, runs Hermes on their Claude subscription, answers them on Telegram or Discord, and shows its dashboard at `https://hermes.<domain>`, where every page the server puts online sits behind one gate (their IP addresses only, then an email and a password). The first argument is the domain (ask if missing and they have several in `cf zones list`), the second the alias (default `hermes`; use it everywhere below). Do every step yourself and only ask for what needs a human (signing in, creating a bot, choosing a password). Talk to the user in their language, short messages, no jargon (never say "token", "tunnel", "reverse proxy" or "systemd" to them; say "access", "the secure link" and "the service").

If you got this skill from a link instead of a local folder, install nothing else from the repo: download a file it links only when a step needs it, with `curl -fsSL https://raw.githubusercontent.com/Melvynx/ai-maxxing-skills/main/skills/setup-vps/<path> -o <scratch>/<file>` (for example `scripts/expose.sh`), and read another skill it names only when you reach it, from `https://raw.githubusercontent.com/Melvynx/ai-maxxing-skills/main/skills/<skill-name>/SKILL.md`.

Never print a token, a key or a password from the Mac or the server, except the one gate password the user needs to save. Tokens travel through pipes from one machine to the other, and anything the user must type (a bot token, an API key, their own password) they type in their own Terminal, never in the chat. Run every remote command as `ssh hermes '<command>' < /dev/null`; when the login user is not `root`, prefix `install` and `expose` with `sudo`, never `hermes-setup` (it asks for `sudo` itself). Never open a port on the server's firewall and never publish a page any other way than `expose add`.

1. Check what is ready: `ssh -o BatchMode=yes hermes true` (otherwise run the `connect-vps` skill), `gh auth status` (otherwise `setup-github`), `cf auth whoami` says authenticated (otherwise `setup-cloudflare`), and `jq --version` (otherwise `brew install jq`). If `CLOUDFLARE_ACCOUNT_ID` is empty and `cf accounts list` shows several accounts, ask which one and export it.
2. Put the two server scripts in place: `scp scripts/hermes.sh scripts/expose.sh hermes:/tmp/`, then `ssh hermes 'install -m 755 /tmp/hermes.sh /usr/local/bin/hermes-setup && install -m 755 /tmp/expose.sh /usr/local/bin/expose'`. Each one prints its commands when run without arguments.
3. Give the server the user's GitHub with [scripts/import-keys.sh](scripts/import-keys.sh) `github hermes`. It installs `gh` there, signs it in with the Mac's access through a pipe, makes `git push` work, and copies their git name and email.
4. Give it Cloudflare with `import-keys.sh cloudflare hermes`. It creates an access named `vps-hermes` that only works from the server's own address (tunnels, DNS, Workers, Pages, R2, KV, D1, firewall, cache) and saves it in `~/.config/cloudflare/env` on the server, loaded by every shell. Rerunning it does nothing while that access works; a new one replaces the old.
5. Install Claude Code and Hermes with `ssh hermes 'hermes-setup install'`, in the background (it takes a few minutes); it skips what is already there and prints both versions.
6. Sign Claude Code in on the server. Tell the user to run `ssh -t hermes claude` in their own Terminal, sign in with their Claude account, open the link it shows, approve, paste the code back, then type `/exit`. Check with `ssh hermes 'hermes-setup claude'`: exit code 5 means not signed in yet; on success it prints `default_model`.
7. Choose the model. The recommended one is that `default_model` (Claude Code's default, `claude-opus-5-5` today) with effort `medium`; if the user asked for another model or effort, use theirs. Run `ssh hermes 'hermes-setup model <model> medium'`; it ends with Hermes answering "OK". On exit code 6, follow the model part of [references/hermes.md](references/hermes.md) (most often the subscription's extra usage). Then copy the Cloudflare access into Hermes with `import-keys.sh hermes-env hermes`.
8. Set up the chat. Ask Telegram or Discord (Telegram is the quickest), then follow its part of [references/hermes.md](references/hermes.md): the user creates the bot and types its token in `hermes gateway setup` in their own Terminal, you run `ssh hermes 'hermes-setup gateway'`, and the step is done when the bot answers their "hello".
9. Build the gate with `ssh hermes 'expose install'`: it installs Cloudflare's connector and Caddy, creates the secure link (named after the server) and starts both, without touching anything else that already runs on the server.
10. Fill the whitelist with the user's addresses, read on the Mac: `curl -4 -fsS https://api.ipify.org` and `curl -6 -fsS --max-time 5 https://api6.ipify.org` (skip the second if it fails), then `ssh hermes 'expose allow <ip>'` for each. Ask if they want other places (office, a second home) and add those addresses too. Tell them in one line that a phone on 4G or a new Wi-Fi gets refused until they ask you to add that address, and that `expose allow any` would drop the IP check but keep the password.
11. Set the login: their email (ask, or take `git config --global user.email`), then `ssh hermes 'expose login <email>'`. It prints a generated password once: give it to the user with their email, tell them to save both in their password manager right now, and never write it anywhere. If they want to choose it, they run `ssh -t hermes 'expose login <email> --stdin'` in their own Terminal and type it (12 characters or more).
12. Put the dashboard online: `ssh hermes 'hermes-setup dashboard'`, then `ssh hermes 'expose add hermes.<domain> 9119 --as-local'`. Exit code 4 means `hermes.<domain>` already points somewhere else: ask before picking another name such as `agent.<domain>`. Then `ssh hermes 'expose status'` must list `site=hermes.<domain>` and no line starting with `UNPROTECTED`.
13. Prove it from the Mac, after a minute for the address to spread: `curl -s -o /dev/null -w '%{http_code}' https://hermes.<domain>` answers `401` (the gate asks for the password). Then ask the user to open `https://hermes.<domain>` in their browser, sign in with the email and password, and say what they see; the Hermes dashboard means done.
14. Tell every agent, in the `## VPS` block that `connect-vps` wrote (brain `AGENTS.md`, `~/.claude/rules/vps.md`, `~/.codex/AGENTS.md` if Codex is installed), keeping every existing line: Hermes runs on the server and answers on Telegram or Discord, the dashboard is `https://hermes.<domain>`, GitHub and Cloudflare work from the server, and to put any page online always run `ssh hermes 'expose add <name>.<domain> <port>'` (and `expose allow <ip>` for a new address), never a tunnel route, an open port or a public bind.

End with a short check list, a check or a cross on each line: GitHub on the server (account name), Cloudflare on the server, Claude Code signed in, Hermes answers (model and effort), chat works (Telegram or Discord), gate built (whitelisted addresses, login email), dashboard online at `https://hermes.<domain>`, no unprotected page, agents told. Then tell the user in 3 lines: send a message to their bot to give the agent a task, open `https://hermes.<domain>` to watch it work, and ask "put my site online on the server" when they want a new page behind the same gate.
