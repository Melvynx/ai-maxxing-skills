Connect Hermes to Discord, almost on its own: you drive the Developer Portal in Chrome AI, the bot's access goes straight from the page to the server without being printed, and `hermes-discord` (from [../scripts/discord.sh](../scripts/discord.sh)) does the rest through Discord's API with the bot itself: the intents, the owner's ID (no Developer Mode needed), a private channel, an access role and who has it. The user only signs in to Discord, types a 2FA code if asked, accepts Discord's developer terms and clicks "Authorize". About 5 minutes.

Run it from `/setup-vps discord [alias]`, or from step 8 of `/setup-vps` when the user picks Discord. Hermes must already answer (steps 1 to 7 done: `ssh hermes 'hermes-setup check'`), and Chrome AI must work (`chrome-ai start` and `dev-browser --help`, otherwise run `setup-dev-browser`). Use one dev-browser page named `setup-discord` for every step, and read each page with `snapshotForAI()` before clicking: Discord speaks the user's language and moves its buttons.

1. Put the script in place: `scp scripts/discord.sh hermes:/tmp/` (from a link, download it first), then `ssh hermes 'install -m 755 /tmp/discord.sh /usr/local/bin/hermes-discord'` (with `sudo` when the login user is not `root`). Then `ssh hermes 'hermes-discord check' < /dev/null`. If it already says `access=ok`, `intents=on`, `owner=... allowed`, a saved server and channel, and `gateway=active`, skip to step 7.
2. The Discord server where Hermes will live. Open `https://discord.com/channels/@me` in Chrome AI; if Discord asks to sign in, the user signs in there (QR code from the phone app is the quickest) and says "done". Ask whether to use one of their servers or create a new one (recommended: a server just for them and their agent). To create it: the "+" (Add a Server) button, "Create My Own", "For me and my friends", name `<Alias>` (the alias with a capital letter), Create. Read the server's ID from the address once it opens (`/channels/<server id>/<channel id>`).
3. The bot. Open `https://discord.com/developers/applications`, "New Application", name `<Alias>`. Discord asks to accept its Developer Terms and Policy: ask the user before you tick the box, then create. Then the "Bot" tab: if the bot has no access yet or you are not sure, click "Reset Token" and confirm; Discord may ask for the user's password or 2FA code, which they type in the page themselves. In the same browser script, read the new access from the page and save it without logging it:

   ```js
   await writeFile("discord-token", token);
   console.log(JSON.stringify({ saved: true, length: token.length }));
   ```

   Then `ssh hermes 'hermes-discord token' < ~/.dev-browser/tmp/discord-token; rm -f ~/.dev-browser/tmp/discord-token`. It answers `token ok: bot <name> (<id>)` and saves `DISCORD_BOT_TOKEN` in Hermes's `.env`. Exit code 2 means what was read is not a bot access (read it again from the page); 5 means Discord refused it (reset it again). Never take a screenshot of the page while the access is shown, never paste it in the chat or in a command line. The access is shown only once: if the page moved on before you read it, reset it again.
4. Turn on what the bot needs: `ssh hermes 'hermes-discord app <server id>' < /dev/null`. It turns on the Server Members and Message Content intents, adds the bot's owner (the user, read from the application) to `DISCORD_ALLOWED_USERS`, and prints `invite=<link>`. If it prints `intents=manual <link>`, Discord refused to change them through the API: open that link (the Bot tab), turn on "Server Members Intent" and "Message Content Intent", "Save Changes", then rerun `hermes-discord check` until it says `intents=on`.
5. Add the bot to the server: open the `invite=` link in Chrome AI. The server is already chosen; the user checks it is theirs and clicks "Authorize" themselves (and solves the captcha if Discord shows one). The link asks for what Hermes needs to read and answer in channels and threads, plus Manage Channels and Manage Roles so it can make its own channel and role in the next step.
6. Set up the server: `ssh hermes 'hermes-discord server <server id>' < /dev/null`. It creates (or reuses) a role `Hermes access`, gives it to the user, creates a private channel `#hermes` that only that role and the bot can see, and saves it as Hermes's home channel where it answers every message without being mentioned (`DISCORD_HOME_CHANNEL`, `DISCORD_FREE_RESPONSE_CHANNELS`, `DISCORD_ALLOWED_ROLES`). Other names: `hermes-discord server <server id> <channel> "<role>"`. Exit code 6 with a permission message means the bot was added without Manage Channels or Manage Roles: open the invite link again and authorize. Exit code 4 lists the bot's servers when it is in several: pass the right ID.
7. Start the chat: `ssh hermes 'hermes-setup gateway' < /dev/null` (it restarts the service so it loads the new settings), then `ssh hermes 'hermes-discord say "Hermes is ready. Write to me here."' < /dev/null`. Ask the user to open `#hermes` in Discord (app or browser) and write "hello" there, without mentioning the bot. In other channels of the server it answers only when mentioned, and in a direct message to the bot always. If the bot answers with a pairing code instead, approve it with `ssh hermes 'hermes pairing approve discord <CODE>'`. If it stays silent, `hermes-discord check`, then `journalctl --user -u hermes-gateway -n 50 --no-pager` (without `--user` for a system service) and `hermes doctor`.
8. Explain access in 3 short lines. Only the user and people with the `Hermes access` role can give Hermes an order, and Hermes acts on the server without asking, so the role is for people they trust like an admin. To let someone in: they first join the server (the user invites them in Discord: right click on the server, "Invite People"), then the user asks "give <name> access to Hermes on Discord" (Hermes runs `hermes-discord access add <username>`); `hermes-discord access remove <username>` takes it back at once, `hermes-discord access list` shows who has it. No restart needed. Never set `GATEWAY_ALLOW_ALL_USERS` or `DISCORD_ALLOW_ALL_USERS`.
9. Tell every agent: in the `## VPS` block (brain `AGENTS.md`, `~/.claude/rules/vps.md`, `~/.codex/AGENTS.md` if Codex is installed), keeping every other line, add that Hermes answers on Discord as `<bot name>` in `#<channel>` of `<server name>`, and that `ssh hermes 'hermes-discord access add|remove|list <username>'` manages who may talk to it.

End with a short check list, a check or a cross on each line: bot created (name), access saved on the server, intents on, bot in the server, private channel and role made, owner allowed, Hermes answered "hello" in the channel, agents told. Then one line: write in `#<channel>` to give Hermes a task.

How it works, for when something breaks. Discord settings live in Hermes's `.env` (`hermes config env-path`); `hermes-discord` keeps the server, channel and role IDs it made in `~/.config/hermes-discord/state`, so every command is safe to rerun and reuses what exists. The intents are application flags: `app` asks for the "limited" ones through `PATCH /applications/@me`, which Discord allows for a bot in fewer than 100 servers. The owner comes from `GET /oauth2/applications/@me` (the team owner for a team app). Access is checked by Hermes against `DISCORD_ALLOWED_USERS` and `DISCORD_ALLOWED_ROLES` on every message, which is why giving or removing the role works without a restart. The bot's access is sent with a header file, never on a command line, and is never printed.
